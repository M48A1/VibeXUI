# VibeXUI

面向个人和小规模使用的轻量多 VPS Xray 管理面板。

## 产品范围

一个主面板统一管理多台 VPS 上的服务器和代理节点。优先减少配置步骤和维护成本。

第一版包含：

- 单管理员登录。
- 服务器添加、移除、在线状态和最近上报时间。
- 每台服务器的 Xray 状态、版本、启动、停止和重启。
- VLESS + REALITY 入站和客户端的创建、修改、启停及删除。
- 分享链接、二维码和跨服务器订阅链接。
- 按服务器、按用户统计上传和下载，并汇总用户的跨服务器流量。
- 配置校验、应用结果、失败回退和配置备份。

暂不包含：多管理员权限、计费、机器人、复杂路由编辑、负载均衡、多数据库和其他协议。
入站与客户端管理参考 [3x-ui 入站](https://docs.sanaei.dev/docs/config/inbounds/)与[客户端](https://docs.sanaei.dev/docs/config/clients/)的设置，保留 VLESS + REALITY / RAW TCP 和跨 VPS 分配方式。

- **入站**：新增、编辑、复制、启停、删除、导入/导出（包含客户端）、批量启停/重置/删除；监听地址、端口、SNI、附加 SNI、目标、REALITY 密钥与 Short ID、指纹、SpiderX、客户端版本和时间差、嗅探、订阅排序和隐藏。
- **客户端**：名称、唯一 Email 标识、可编辑或重新生成的 UUID、Flow、按入站覆盖 Flow、VLESS 反向代理标签、默认及按入站覆盖的 IP 上限、总流量、到期或首次使用计时、定时重置、自动续期、续期预览、订阅标识、Telegram ID、分组、备注和外部节点分享链接。
- **批量管理**：从客户端模板批量创建独立 UUID/订阅标识的用户；启停、删除、清零流量、增加有效期或额度、分配/移除入站、设置分组或 Flow。支持在线、到期、额度用尽、未分配入站和分组筛选；清理耗尽用户会保留设置了自动续期的用户。
- **流量策略**：入站与客户端各自拥有额度和到期策略，任一层不允许访问时撤下对应配置。入站按其所有用户的上传＋下载计量；客户端流量跨全部已分配入站汇总。0 为不限，手动重置保留历史累计、到期时间和自动重置计划。
- **定时清零**：入站和客户端均可选不重置、每小时、每天、每周一、每月指定日；按面板系统时区执行，短月取最后一天。客户端原有按设置日期起算的月、季度、半年、年周期仍可继续使用。修改重置规则只重新计时，不清零已用额度。
- **自动续期**：客户端到期时按固定天数、每周指定星期或每月指定日期延长到期时间并重置流量。次数上限 0 为不限，离线期间错过的周期也计入次数；剩余次数不足以续到未来时保持到期状态。手动停用的用户不会自动续期。定时清零流量与续期相互独立，续期必须具有到期时间或已激活的首次使用有效期。
- **订阅**：多个客户端可使用同一订阅标识合并链接；仅包含策略允许的用户和入站。订阅响应包含已用流量、限额与到期时间。更改订阅标识立即使旧地址失效；外部节点流量由外部服务管理。

Telegram ID 是用户关联信息，当前不含 Bot 通知或自助服务；反向代理标签会下发到 Xray，但实际反向通信还需要客户端配置及服务端路由。入站导入/导出使用 VibeXUI JSON 格式，不直接导入 3x-ui 数据库。导出入站包含其私钥和客户端凭据。

升级此功能需同时替换主面板和各 VPS 的 Agent，以采集入站流量与全部用户的在线信息。旧数据库中的 UUID、订阅标识、历史流量及周期设置保留，入站历史从新 Agent 开始采集。

## 架构草案

- 主面板：Go、SQLite、内嵌 Web 静态资源，保存服务器和节点配置。
- VPS Agent：独立 Go 程序，管理本机 Xray-core 进程、校验并应用配置、上报状态。
- Xray-core：独立二进制，实际处理代理流量。
- Agent 主动连接主面板，通过 HTTPS 认证和获取任务，避免额外开放 Agent 管理端口。
- 每台服务器使用独立凭据，首次注册使用短期、一次性注册令牌；凭据可撤销。
- 主面板为每次配置分配版本，区分期望版本和实际应用版本。
- Agent 串行应用任务，先校验再替换；应用失败恢复上一份配置并回报错误。
- 订阅访问使用独立随机令牌，不暴露管理员凭据或服务器注册凭据。

## 实现顺序

1. 主面板登录、数据库、服务器列表和 Agent 注册及心跳。
2. Xray 进程管理和带版本的配置下发、校验、回退。
3. VLESS + REALITY 节点、客户端、分享链接和订阅。
4. 基本流量统计、备份和 Linux 安装流程。

## 当前状态

当前版本 0.4.0 已实现主面板、Agent、VLESS + REALITY 入站、跨服务器订阅、二维码、按用户流量统计和配置回退。面板静态页面嵌入二进制，无需 Node.js 或单独部署前端。

服务器、入站和用户列表支持搜索及状态筛选；总览提供接入步骤和待处理服务器提示。服务器详情显示注册状态、配置同步状态和排障信息；用户流量详情显示各服务器的累计贡献，并可将筛选后的用户流量导出为 CSV。CSV 不包含 UUID 或订阅令牌。

配置备份为 JSON 导出，尚无一键恢复。尚未验证真实多 VPS 和公网客户端连通性。安装脚本需在目标 Linux 上运行，当前提供的本地测试不代表已完成公网部署。

## 本地运行

需要 Go 1.26 或更新版本。

```bash
make build
# 首次启动时设置密码；后续使用数据库中的账号。
export VIBEXUI_PASSWORD='替换为至少12字节的强密码'
./dist/vibexui-panel -public-url http://localhost:8080
```

打开 http://localhost:8080，默认用户名 `admin`。可在首次启动前通过 `VIBEXUI_USERNAME` 修改用户名。会话有效期 12 小时，面板重启后需重新登录。数据库默认位于 `data/panel.db`。

本次开发预览的随机初始密码保存在 `data/initial-password`（权限 0600），该文件不随源码交付或提交。密码数据库中使用 bcrypt 保存。

## 连接服务器

1. 在主面板添加服务器，填写客户端实际使用的公网 IP 或域名。
2. 公网 HTTPS 面板会显示该服务器专属的一键安装命令。复制到对应 VPS 执行即可；首次安装自动下载 Agent、校验 SHA256、安装 Xray-core、注册服务器并配置 systemd 开机启动。目前一键安装支持 Debian/Ubuntu，架构为 amd64、arm64。
3. 服务器上线后，在主面板创建入站节点、添加用户并分配节点。

安装方式参考 [X2rayVlessInstall.sh](https://github.com/M48A1/StepByStep/blob/main/X2rayVlessInstall.sh) 的自动下载和服务安装流程。Agent 安装脚本由主面板的 `/install/agent.sh` 提供；Agent 二进制下载需要有效的一次性注册令牌，注册后令牌失效。默认 Xray 版本固定为已验证的 `v26.3.27`，使用官方 release 的 SHA256 校验值。

主面板需要保存要分发的 Linux Agent 二进制。在开发机运行 `make linux`，启动面板时通过 `-downloads-dir dist` 指定发行目录；目录结构为：

```text
dist/
  linux-amd64/vibexui-agent
  linux-arm64/vibexui-agent
```

默认发行目录为 `dist`。Linux 主面板安装脚本会从上传的 `dist/linux-amd64` 和 `dist/linux-arm64` 目录复制 Agent 至 `/var/lib/vibexui/downloads`，并配置服务使用该目录。缺少某架构的文件时，安装命令会提示下载失败，需先补齐对应文件。

一键安装保留已有的 `/usr/local/bin/xray`，不覆盖其他 Xray 服务或配置；若其他服务占用节点端口或统计端口，请先处理冲突。已有 Agent 安装会停止安装流程并提示按下文重新注册，不会覆盖凭据。Agent 的注册步骤完成后才创建 systemd 服务；如果服务安装阶段失败，本地凭据已经保存在 `/var/lib/vibexui/agent/agent.json`，可按下方手动服务安装方式完成配置。

本机 HTTP 调试面板仍显示手动启动命令。手动方式适用于其他使用 systemd 的 Linux 系统：先将对应架构的 Agent 和官方 Xray-core 放置到 VPS，再使用面板显示的一次性注册令牌启动 Agent：

```bash
export VIBEXUI_REGISTRATION_TOKEN='面板生成的注册令牌'
./vibexui-agent \
  -panel https://panel.example.com \
  -server-id '面板生成的服务器ID' \
  -data-dir /var/lib/vibexui/agent \
  -xray /usr/local/bin/xray
```

Agent 将独立凭据保存在数据目录的 `agent.json`。注册成功后可清除 `VIBEXUI_REGISTRATION_TOKEN`，重启使用已保存的凭据。注册令牌只能使用一次，有效期 30 分钟。若注册响应丢失，或需要重新注册，先停止 Agent，在主面板的服务器“更多”中生成新令牌，删除对应数据目录中的 `agent.json`，然后带新令牌启动。删除该文件会重置本地流量累计统计。

开发时可使用 `http://localhost:8080` 或回环 IP；公网 Agent 只接受 HTTPS，不提供跳过证书验证选项。不要同时启动多个 Agent 使用同一个数据目录。每台 VPS 单独安装一个 Agent，该 Agent 独占它管理的 Xray 进程和配置。

创建节点时填写监听端口、SNI 和 REALITY 目标，例如目标格式 `example.com:443`。请自行选择可达、支持 TLS 1.3 且证书与 SNI 匹配的站点。创建用户并分配节点后，可复制订阅地址或扫描订阅二维码。订阅输出为 Base64 编码的 VLESS 分享链接列表，尚不提供 Clash YAML。

REALITY 配置和统计接口参考 [Project X 传输配置](https://xtls.github.io/en/config/transport.html)及[统计文档](https://xtls.github.io/en/config/stats.html)。已验证 Xray-core `v26.3.27`；节点配置使用 RAW/TCP + REALITY + Vision。统计 API 仅监听本机 `127.0.0.1:10085`，该端口不可分配给代理节点。

## Linux 安装与自动 HTTPS

在开发机交叉编译：

```bash
make linux
```

生成 `dist/linux-amd64/` 和 `dist/linux-arm64/` 两套二进制。安装主面板时上传整个 `dist` 目录及 `scripts/install.sh`，以便分发两种架构的 Agent；手动安装 Agent 时只需上传目标架构目录和安装脚本。以下命令在目标服务器运行。

安装主面板：

```bash
sudo bash scripts/install.sh panel dist/linux-amd64
```

脚本只需输入面板域名，自动生成随机管理员账号（`vx_` 加 12 位随机十六进制字符）和 48 位随机密码，不再要求手动填写账号密码。随后安装 systemd 服务、配置 Caddy 反向代理，并由 Caddy 自动申请和续期 HTTPS 证书。域名的 DNS A/AAAA 记录必须正确指向主面板 VPS，80/443 端口须可达。Debian/Ubuntu 缺少 Caddy、OpenSSL 或 curl 时通过 apt 安装；其他发行版请先安装这些工具。

安装脚本先等待面板启动，再等待最多约 90 秒验证域名的 HTTPS 证书和反代响应。验证通过后输出登录地址、随机管理员账号和密码；初始凭据保存在 `/etc/vibexui/panel.env`，文件权限为 0600，仅 root 可读。若证书暂未签发成功，会明确提示待处理、输出已生成的登录凭据并以非零状态退出；Caddy 继续运行和重试，无需重新生成账号或重装。可用 `journalctl -u caddy -n 50` 查看原因。

安装过程的输出示例（实际账号密码每次新安装随机生成）：

```text
安装完成，HTTPS 证书已验证，Caddy 将自动续期。
登录地址：https://panel.example.com
管理员账号：vx_随机字符
管理员密码：48位随机密码
```

Caddy 站点写入 `/etc/caddy/vibexui-panel.caddy`，通过 import 加入已有 Caddyfile。修改前备份为 `/etc/caddy/Caddyfile.vibexui-backup`，校验失败恢复原配置。若已有同域名站点或 80/443 被其他 Web 服务占用，请先处理冲突。脚本拒绝覆盖已有 VibeXUI 服务配置。

手动安装 Agent（Web 一键安装已经包含此流程；手动方式先将官方 Xray-core 安装到 `/usr/local/bin/xray`）：

```bash
sudo bash scripts/install.sh agent dist/linux-amd64
```

安装时填写面板地址、服务器 ID 和一次性令牌。Agent 使用非 root 用户运行，通过 `CAP_NET_BIND_SERVICE` 支持监听 443 等低端口。主面板本身只监听 `127.0.0.1:8080`。

```bash
systemctl status vibexui-panel
systemctl status vibexui-agent
journalctl -u vibexui-agent -f
```

主面板与 Agent 可以同机部署。此时 Caddy 已占用 443，节点必须使用其他可用端口或其他 IP。每个代理节点的端口需在 VPS 防火墙中放行，Agent 无需额外入站管理端口。

## 配置下发与运行行为

- Agent 默认每 10 秒上报一次，35 秒未上报标记离线。
- 节点和用户变更增加对应服务器的配置版本；服务器列表分别显示期望版本和已应用版本。
- 配置先执行 `xray run -test`，校验成功才替换并重启。启动失败恢复上一配置，错误在面板显示；失败任务会在后续轮询中重试。
- 配置应用重启 Xray，已有连接会短暂中断。统计为轮询累计值，重启时最后一个采样间隔可能少计。
- Agent 同时读取 Xray 的入站计数和 `user>>>用户ID>>>traffic` 计数，分别累计服务器与用户流量，避免把出站或用户流量再次加到服务器总流量。用户详情展示上传、下载和各台服务器的贡献。
- 累计流量和统计周期标识保存在 Agent 数据目录；面板使用每台服务器的累计值计算增量，重复或较旧的上报不会重复计数。Agent 数据目录重建后使用新周期，从新计数继续累计；移除服务器仍保留已上报的用户历史流量。
- 按用户统计从升级后的 Agent 开始，无法回填旧版本未采集的历史数据。尚未产生用户计数时，界面显示“尚未采集到用户流量”。面板每 5 秒检查到期，并在 Agent 上报时检查汇总额度；Agent 通常每 10 秒同步。可能超用，离线 VPS 或面板停机期间无法及时撤下配置，恢复后执行。重置前发生但晚到的上报计入新额度。
- 面板断线时，Agent 保持本机现有 Xray 运行；恢复连接后继续同步。
- 停止或退出 Agent 会停止它启动的 Xray；systemd 服务重启后重新连接面板并按期望状态运行。
- 移除服务器或重新注册会立即撤销 Agent 凭据，但不会通过已撤销凭据远程停止旧进程；请先停止服务器服务再移除。
- 用户停用后订阅立即失效；代理访问在 Agent 应用配置后停用。离线 VPS 的旧配置会继续生效，直到重新连接。
- JSON 配置备份包含私钥和订阅令牌，不包含管理员密码或 Agent 凭据。完整迁移还需要 SQLite 数据库和各 Agent 的数据目录；复制 SQLite 前请停止面板或使用 SQLite 备份工具，不能只复制正在写入的数据库主文件。

## 更新

停止对应 systemd 服务，备份数据库和配置，将新版本二进制替换至 `/usr/local/bin/vibexui-panel` 或 `/usr/local/bin/vibexui-agent`，再启动服务。已有安装无需重新运行安装脚本。当前未提供自动更新及数据库版本迁移工具。

升级到 0.2.0 时先更新主面板，再更新各 VPS 的 Agent；保留原数据库及 Agent 数据目录。主面板的 `/var/lib/vibexui/downloads/linux-amd64/vibexui-agent` 和 `linux-arm64/vibexui-agent` 也需要替换为新版本，以供新 VPS 安装。旧 Agent 可继续向新面板上报服务器流量，但按用户统计需要新 Agent。

## 每个用户、每个入站的在线 IP 限制

在入站列表点击“客户端 → 客户端设置”（或在客户端与订阅页编辑用户），在已分配入站旁输入“限制 IP 数”（0–128，0 表示不限）。限制以“用户 × 入站”为单位：同一用户可在香港入站设 1、日本入站设 2；不同入站独立计数，超限只撤下该用户在对应入站的配置，其他用户和该用户的其他入站仍允许访问。

Agent 使用 Xray 的在线统计 API 采集当前连接的来源 IP，按同一入站的 IP 去重。这里不是设备数或连接数：同一 NAT 出口的多个设备算 1 个 IP，同一设备的 IPv4 与 IPv6 可算 2 个。短连接在两次采样之间结束可能不会被计入。129 个以上显示为“至少 129”。未设置 IP 上限的用户/入站也会采集在线信息，用于客户端的在线筛选和最近在线时间；未设置上限不会因 IP 数量而停用。

采样发现数量超过上限后，主面板暂停对应用户/入站约 60 秒，再自动恢复；持续超限会再次暂停。暂停期间该入站不出现在新订阅内容中，代理访问在 Agent 应用配置后停止。已有客户端缓存的节点链接会被 Xray 配置限制。当前通过重新应用 Xray 配置执行，**同一 VPS 上其他连接也可能短暂重连**，暂停范围指用户资格，不代表只断开超出的那个 IP。

这是轮询检测后的停用策略，并非在握手时严格保留前 N 个 IP；一般需等待下一次约 10 秒的上报及配置同步，超限到停用之间可有短暂超用。面板或 Agent 离线时无法保证及时执行。35 秒前的样本不用于新停用；统计失败或旧 Agent 未提供样本显示“未知/采集异常”，不会冒充 0 个在线 IP。

此功能需要更新面板和 Agent，并使用支持 `statsUserOnline`、`statsgetallonlineusers` 与 `statsonlineiplist` 的 Xray；一键安装固定的 v26.3.27 支持这些接口。升级 Agent 并同步配置后开始采集，不追溯旧连接历史。原数据库、UUID 和订阅令牌保留，无需重新注册 Agent。API 的用户保存请求可传 `limitIp` 设置默认上限，用 `nodeIPLimits: {"入站ID": 2}`，省略则保留已有上限；网页“IP 限制”可查看各入站的上限、当前样本和暂停截止时间。
